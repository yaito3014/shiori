# 0003 戻すのプレビューと、状態から作るお知らせを拡張 API に足す

## 状況

shiori-vrchat は、戻す先で `Packages/vpm-manifest.json` が変わるときに確認ダイアログで知らせ、戻したあとは
VCC / ALCOM で Resolve するまで知らせ続けたい（提案 A2）。既存の `GetRestoreWarning` は同期で、受け取るのは
戻す先の履歴が「その時に」変えたファイルだけなので、今と戻す先の差がわからない。戻したあとに知らせを出す場所もない。

## 選択

- `RestorePreview`（戻す先と、HEAD と戻す先で内容が違うパスの一覧）を、確認ダイアログの前にコアが作る。
  拡張は非同期の `GetRestoreWarningAsync(context, preview, ct)` で受け取る。既定実装は従来の
  `GetRestoreWarning` を呼ぶので、既存の拡張はそのまま動く。プレビューは拡張があるときだけ計算する。
- `GetNoticesAsync(context, ct)` は、表示を更新するたびに呼ばれ、その時点のプロジェクトの状態から
  `ExtensionNotice`（見出し・文言・詳細・ボタン）を返す。原因が解消すれば拡張が返さなくなり、自然に消える。
  コアは「出した / 消した」を覚えない。描画は未完了の拡張手順と同じパネルで、手順のあとに並べる。
- `IGitRepository.ReadFileAtAsync(revision, path)` で、任意の履歴時点のファイル内容を読めるようにする
  （戻す先のマニフェストを比べるため）。無い、またはフォルダなら null。

## 理由

- 状態から作るお知らせは、Unity の再起動やドメインリロードをまたいでも正しく、保存する情報がいらない。
  「戻した」というイベントを覚える方式だと、VCC で解決したことをコアが知る手段がない。
- 拡張は今までどおり UI を持たず、文言とボタンだけを返す（ADR 0002）。

## 捨てた案

- 戻したあとに一度だけ出す通知（イベント方式）: 再起動で消える、解決しても残る、のどちらかになる。
- 閉じるボタン付きのお知らせと、その既読状態の保存: 状態から作れば不要。必要になったら UserSettings に足す。
- 未保存の変更もプレビューに含める: 確認ダイアログが別に扱っており、二重に知らせることになる。

# 0007 受信で合わせる、決められないファイルはファイルごとに選ぶ

## 状況

M5 の見取り図は「UnityYAMLMerge を git のマージツールに設定。失敗時はファイル単位で『自分 / 相手』を選ぶ UI」。
これまで受信は fast-forward だけで、2 台の PC で別々に保存すると止まっていた。ユーザーに確認して次を決めた。
受信は合わせる。失敗したファイルはファイルごとに選ぶ。設定はウィザードの手順にする。未保存の変更は先に保存する。
決めきれていないマージは途中のまま残し、「やめる」で戻せる。

## 選択

- UnityYAMLMerge は mergetool ではなく merge driver にする（`.git/config` の `merge.unityyamlmerge.driver` と
  `.gitattributes` の `shiori-merge` ブロック）。git が両方で変わったファイルにだけ自動で使う。
  コマンドは `"<tool>" merge -h --force --fallback none %O %B %A %A`。git の一時ファイルには拡張子がないので
  `--force` がないと何もせずに失敗する（実機で確認）。`-h` と `--fallback none` で画面を出さない。
- 設定は「Unity のマージ設定」手順。コアの手順も拡張 API（`CoreSetupSteps`）で出すので、ウィザード・
  かんたんモードの通知・Project Settings に同じ形で並ぶ。Unity を入れ替えてパスが変わると「更新する」が出る。
  リポジトリがまだなければ `git init` してから書く（最初の保存より前の手順のため）。
  任意の手順で、「使わない」と「使うのをやめる」（確認のあと、ドライバーとブロックを消す）は
  `ProjectSettings/Shiori.json` のコアの区画に `mergeDriver: off` を残す。ブロックがあればそちらを優先する。
  コアのブロックの `merge=unityyamlmerge` は残るが、定義のないドライバーは git がテキストのマージに戻す（実機で確認）。
- 受信は分かれていたら `git merge`（メッセージ「ほかの PC の保存と合わせました」）。詳細モードのプルとマージも同じ。
- 止まったら、競合したファイルには自分の版を `checkout --ours` で入れておく。Unity が競合マーカーや
  半分だけ合わさったシーンを読み込まないため。上書きするのは git の出力だけ（マージは作業ツリーがきれいなときだけ始める）。
- 選ぶと `checkout --ours|--theirs` + `add`、その側で消えていれば `rm`。止まったあとにファイルが変わっていたら
  （Unity で編集したなど）確認してから上書きする。アセットと .meta は 1 行で一緒に決める。
- かんたんモードは最後の 1 つを選んだらすぐ保存する。詳細モードは「マージをコミット」かツールバーのコミット。
- 途中の間は、保存・戻す・送信・受信・バリエーション（詳細モードはコミット・プッシュ・プル・ブランチ・スタッシュ）を止める。
  「やめる」は確認のあと `git merge --abort`。

## 理由

- driver なら git がファイルを選んで呼ぶ。mergetool は競合のあとに人が呼ぶもので、結局すべてを手で開くことになる。
- 決めるまで自分の版を置いておけば、途中でも Unity は普通に開ける。

## 捨てた案

- 自動で毎回 `.git/config` を書く: ユーザーが「手順にする」を選んだ。
- 競合したらすぐ中止する（M4 の動き）: 受信では、分かれた履歴がいつまでも合わせられない。
- 1 つのダイアログで全部選ばせる: 閉じたら途中が残らない代わりに、Unity で中身を見比べられない。

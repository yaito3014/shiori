# 0006 バリエーションはブランチ、マージは詳細モードだけ

## 状況

M4 の見取り図は「ブランチを `shiori/<name>` で作成・切替。切替時の Library 再生成について警告」の 1 行だけ。
未保存の変更があるときの切り替え、合わせる（マージ）、削除はユーザーに確認して決めた。

## 選択

- バリエーション「衣装A」はブランチ `shiori/衣装A`。名前に使えない文字は `-` にし、最後は `git check-ref-format --branch`
  で確かめる。Windows では大文字小文字だけ違う名前がぶつかるので、作るときに大文字小文字を無視して重複を見る。
  `main` / `master` は「メイン」と表示し、ほかのブランチ（詳細モードや外で作ったもの）はそのままの名前で出す。
- 作るのは `git switch -c`。ファイルは変わらないので確認は出さず、未保存の変更はそのまま新しいバリエーションに入る。
- 切り替えは `git switch`。前に、変わるファイルの数と読み込み直しを知らせる（Library は消さない）。未保存の変更があれば
  「保存してから切り替える / 変更を持っていく / キャンセル」。持っていけないとき git は拒否して何も変えないので、
  その一覧を出す。ほかの PC で作られたものは `git switch -c <name> --track origin/<name>`。
- 拡張には `GetSwitchWarningAsync` を足した（戻すの警告は文言が「戻す」なので流用しない）。
- 削除は確認のあと `git branch -D`、送信先にもあれば先に `git push origin --delete`（失敗してもローカルは残る）。
  確認には、今のバリエーションにない保存の数を出す。今のバリエーションとメインは消せない。
- マージは詳細モードだけ。作業ツリーがきれいなときだけ `git merge --no-edit` し、競合したらすぐ `git merge --abort`
  して競合したファイルを知らせる（競合の解決は M5）。

## 理由

- ブランチにしておけば、送信・受信・履歴がそのまま「今のバリエーション」に効く。
- かんたんモードでマージを出すと、競合の扱いが要る。M5 まで出さない。

## 捨てた案

- 未保存の変更をバリエーションごとに自動で stash する: 動きが見えにくく、stash が増え続ける。
- 削除をローカルだけにする: 送信先に残ったものが「ほかの PC」として一覧に戻ってくる。
- マージで競合したら作業ツリーに残す: 解決する画面がまだない。

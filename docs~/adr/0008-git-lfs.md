# 0008 Git LFS は推奨の手順にし、使えない PC では取り出す操作を止める

## 状況

M1 から LFS は「検出と案内のみ」で、必須か推奨かは未決定だった。ユーザーが LFS 対応を急ぎで求め、次を選んだ。
推奨（任意の手順、「使わない」も選べる）。LFS を使うプロジェクトでこの PC が使えないときは警告し、取り出す操作を止める。
これから保存するファイルだけを LFS に入れ、履歴は書き換えない。ロックは入れない。

## 選択

- 手順「大きなファイルの設定」をコアの手順（`CoreSetupSteps`）に足す。`git lfs install --local`（フィルターと pre-push
  フック）と `.gitattributes` の `shiori-lfs` ブロック。対象は画像・モデル・音・動画・フォント・アーカイブ。
  属性のパターンは大文字小文字を区別するので、大文字の拡張子も並べる。Unity のテキストアセットは入れない（マージのため）。
- 「使わない」は `ProjectSettings/Shiori.json` のコアの区画に `largeFiles: off`。すべての PC で同じになる。
- 「使っている」は `.gitattributes`（ルート）に `filter=lfs` の行があること。ユーザーが自分で書いた行でもよい。
  「この PC で使える」は、git-lfs があり、lfs フィルターが（どの scope でも）設定され、pre-push フックが LFS のもの。
- 使っているのに使えない間は、受信・戻す・バリエーション/ブランチの切り替えとマージ・取り出す/スタッシュ適用を止める
  （ボタンを無効にし、処理の入口でもダイアログで止める）。保存と送信は止めない。
- 「この PC で使えるようにする」は `lfs install --local` のあと、送信先があれば `lfs pull`（作業ツリーを書き換えるので
  AssetDatabase を止めて最後に Refresh）。

## 理由

- LFS なしで取り出すと、テクスチャやモデルの代わりにポインタのテキストが Assets/ に入り、Unity が壊れたアセットとして読み込む。
- pre-push フックがないと送信で LFS の中身が上がらず、ほかの PC で取り出せなくなる。

## 捨てた案

- 必須にする: LFS を入れられない環境で先に進めなくなる。
- `git lfs migrate` で履歴も移す: すべての PC で強制 push と取り直しが要る。
